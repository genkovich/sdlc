# api-forge — drift check, report shape, reconcile, conflicts

The contract is a **derived** artifact: `data-model.md` (typed shape) + `sad.md` §6 sequences
(error branches, async actors) + `PRD.md` §4/§5 (endpoint list, observable outcomes) → OpenAPI.
This file is the operational detail for step 8 of the spine — what the report holds, what
each drift point compares, and how the verdict is derived. The spine ([`../SKILL.md`](../SKILL.md))
is the source of truth for when this runs.

## `api-sync-report.md` shape

Written to `docs/features/<slug>/contracts/api-sync-report.md` next to the YAML, **on every run —
`FAIL` included** (a failing state that lives only in the chat is gone after `/clear`). A header
block, then four sections.

### Header — verdict first

```
# api-sync-report — <slug>

**Verdict:** PASS | PASS (with deferrals) | FAIL
**Run at:** <ISO timestamp> (<run number>, mode: first run | --reconcile)
**Generated by:** `api-forge` (sdlc plugin v<X.Y.Z>) protocol step 8 (inline drift check)
**Sources read:** PRD.md ✓ · data-model.md ✓/✗ · sad.md §6 ✓/✗ · adr/*.md ✓/✗ · CONTEXT.md ✓/✗
**Scenario:** A | B — one line on why
**Contract version:** `info.version: <semver>`, OpenAPI 3.1.0
**Rules file:** `.claude/rules/openapi.md` bootstrapped | already present | n/a (non-HTTP surface)
```

The verdict is **derived from Section B + Section C + Section D**, never typed from a feeling.
Exactly one of three values, so two people reading the same findings reach the same word:

| Verdict | Rule |
|---|---|
| `PASS` | Scenario A. All 5 points ✓ (plain or accepted-as-is). `unresolved_origins` empty. `Deferrals`: none. |
| `PASS (with deferrals)` | Core points 1–3 are ✓ (plain or accepted-as-is) — nothing is left open on them — but something is consciously parked and listed in `Deferrals` with a next step: scenario B (`unresolved_origins` non-empty), a supporting point 4–5 marked `✓ (deferred: …)`, any finding resolved as Save-as-OQ, a sequence gap left for `complete-sequence-diagrams`, or a default deviated from without an ADR yet. |
| `FAIL` | Any core point 1–3 is still ✗ after the 4-state resolution (the human chose Fix-the-source-first, or an ✗ was left open), or ≥3 open flags, or the contract carries a field with no origin in any input. The contract is **not final**: the report names the artifact to fix and the command to run (`/sdlc:write-prd`, `/sdlc:complete-sequence-diagrams`, `/sdlc:generate-data-model`), then `/sdlc:api-forge <slug> --reconcile`. No handoff to `break-tasks`. |

Per-point marks: **✓** (holds, or Accept-as-is recorded with the reason — a conscious decision,
nothing pending), **✓ (deferred: one line)** (holds for now, a later run tightens it — e.g.
"no error registry yet, reconcile when the repo defines it"), **✗ (one-line diagnostic)**.
Accept-as-is on a core point is a ✓, not a deferral: the mismatch has an owner's decision behind
it and will not change on its own. A deferral is anything that *waits for* a later artifact or run.

### Section A — field-origins table

One row per `(operation, schema_field)` pair, so every field in the contract is traceable:

```
| schema_path                | origin                                  | confidence |
|----------------------------|-----------------------------------------|------------|
| createLesson.title         | data-model.md → lesson.title (≤200)     | high       |
| createLesson.module_id     | data-model.md → lesson.module_id (FK)   | high       |
| listLessons.next_cursor    | derived (cursor wrapper convention)     | high       |
| publishLesson.published_at | inferred from PRD §5 AC-4, no column    | low        |
```

- **high** — field maps to a `data-model.md` column with a matching type/constraint.
- **medium** — field derived from a PRD field name with no column yet (e.g. a computed/response-only field).
- **low** — field inferred from a sequence message name only; flag it for confirmation.

A `low` row is **declared incompleteness**, not an error — it tells the team what `--reconcile`
will tighten when the model gains that column. Never hide it.

### Section B — drift findings (5-point checklist)

Each point is ✓, ✓ (deferred: …) or ✗ with a one-line diagnostic on ✗. Points 1–3 check the
**forward** direction (the contract was derived correctly from its sources); points 4–5 check
the **back-feed** direction (every source is covered by the contract).

1. **Endpoint ↔ data-model** *(core)* — every endpoint reads/writes ≥1 entity in `data-model.md`
   (e.g. `POST /lessons/{id}/publish` mutates `lesson.status`). In scenario B (data-model absent),
   fall back to: every endpoint maps to a PRD §4 user story.
2. **Error code ↔ repo error definition** *(core)* — every `code` in an `Error` response exists in
   the repo's error definitions, **checked in the form the repo uses**. Detect that form first —
   a constants/enum file, an error registry, a sentinel module, a generated table — and match
   against it; do **not** assume any one language or a Go-style `domain/errors.go`. If the repo
   has no central error list yet, record "no error registry found — codes are the contract's
   proposal; reconcile when the repo defines them" rather than failing the point.
3. **Validation ↔ constraint** *(core)* — `maxLength` / `pattern` / `enum` in the contract align
   with the bounded types and uniqueness/format constraints in `data-model.md`. Scenario B:
   record "deferred to reconcile — no data-model.md yet". On a conflict, take the **stricter**
   value and flag both — the human resolves which artifact is wrong.
4. **Entity / AC ↔ endpoint (coverage)** *(supporting)* — the reverse of point 1. Every entity in
   `data-model.md` is surfaced by ≥1 operation **or** explicitly marked *intentionally internal*
   (an audit table, an authz primitive — say why); every PRD §5 AC maps to ≥1 operation/response;
   every operation maps to a §4 user story + ≥1 AC. An entity with no story and no "internal"
   reason gets a `# unused-in-prd` note and a question to the user; an AC with no operation is a
   missing endpoint or a PRD line that should not be there — ask. In scenario B (no model): every
   §4 story has ≥1 operation and every AC has ≥1 response.
5. **OpenAPI ↔ sequence** *(supporting, both directions)* — the methods, paths, and outcome
   branches the §6 sequences imply match the contract, and every `alt`-branch has a response.
   Because §6 participants are generic (`<client>`/`<service>`/`<data-store>`), match on the
   **flow and its `alt`-branches**, not on participant names — a branch like `alt not owner` must
   have a corresponding error response. The reverse: any error/authorization response the contract
   needs but **no §6 flow shows** is a **sequence gap** — not a contract bug, a hole upstream.
   Mark the point `✓ (deferred: …)` when the team parks it, and offer **Fix-the-source-first**:
   re-open `/sdlc:complete-sequence-diagrams <slug>` (draw the missing branch) or
   `/sdlc:write-prd <slug>` (add the missing AC) before finalizing. Mismatch the other way
   usually means a sequence was drawn before the contract was finalized and never updated.

A **core** point (1–3) failing — or **≥3 flags** of any kind in one run — pauses the run and is
surfaced to the user before writing. A **supporting** point (4–5) failing becomes a
`✓ (deferred: …)` with a `Deferrals` entry, or a ✗ with a follow-up note if the team does not
want to park it — either way it never blocks on its own. Resolve each finding via the 4-state
actions:

- **Accept as is** — record the mismatch as accepted (e.g. an intentionally internal entity with
  no endpoint), move on.
- **Fix the contract** — regenerate the affected operation/schema to match the source.
- **Save as Open Question** — park it with owner + due; the field/endpoint stays with a
  `# unresolved` note until answered.
- **Fix the source first** — STOP; the contract waits for the user to correct `data-model.md` /
  the sequence / the PRD (this skill never edits sources). The report is still written, with
  `**Verdict:** FAIL` and the command to run next.

How each action lands in the verdict: Accept-as-is → ✓ (reason recorded); Fix-the-contract →
✓ after regeneration; Save-as-OQ → `Deferrals` entry → at best `PASS (with deferrals)`;
Fix-the-source-first → `FAIL`.

### Section C — unresolved_origins

Empty in scenario A. In scenario B — list of fields whose origin is "inferred from PRD/sequence,
needs confirmation when data-model.md arrives". Each entry: `schema_path | current origin | what
reconcile would tighten`. A non-empty section caps the verdict at `PASS (with deferrals)`.

### Section D — Deferrals

Every item the run consciously parked, one line each: `what | why parked | next step (command or
owner + due)`. Sources: a `✓ (deferred: …)` on points 4–5, a Save-as-OQ, a sequence gap, a
default deviated from without an ADR, scenario B itself. Write `none` on a plain `PASS` — the
word has to be there so a reader knows the section was not forgotten. This list is what the next
`--reconcile` run reads first.

## Reconcile semantics (`--reconcile`)

Run after an upstream artifact changed — most often `data-model.md` arrived (or was tightened)
after a thinner first pass. The reconcile pass:

1. Re-reads all inputs.
2. Tightens loose types where the model now carries a constraint (a bare `string` becomes
   `string` + `maxLength`; a free field becomes an `enum`).
3. Refreshes the Section A confidence column (`low`/`medium` → `high` where a column now backs the field).
4. **Surfaces real drift** — any field that *had* an inferred origin but *now disagrees* with the
   model. This is the load-bearing output: stale incompleteness becomes either resolved or a
   genuine conflict, and the two never get confused.
5. **Re-derives the verdict** from the refreshed Sections B–D and re-reads the previous report's
   `Deferrals` — each entry is closed (and said so) or carried forward; a carried deferral keeps
   the verdict at `PASS (with deferrals)`.

`info.version` is never bumped here — the user bumps semver explicitly with a CHANGELOG line.

## Conflict table — human in the loop

| Conflict | Skill action |
|---|---|
| Field in `data-model.md` with no story in PRD covering it | Add it to the schema with a `# unused-in-prd` note in the report; ask the user. |
| A §6 sequence references a flow that maps to no endpoint | Flag `# orphan-sequence` in the report; ask (forgotten endpoint? internal job?). |
| PRD §5 constraint contradicts a `data-model.md` constraint | Take the stricter value; flag both; the human resolves which artifact is wrong. |
| Existing `openapi.yaml` has a field absent from every source | Keep it with a `# manual-addition` note; flag in the report. |
| A field disappeared from `data-model.md` | Keep it in the YAML with a `# stale` note; surface it — the human removes from the contract or restores in the model. |

If ≥3 flags appear in one run, pause, list them, and ask whether to continue or fix the sources first.

## Defaults (deviation by ADR only)

A fixed minimum, not invented per feature; an `adr/*.md` overrides any of them and the report
records "deviation by ADR-NNNN". The same set is written into the repo once as
`.claude/rules/openapi.md` (spine step 2, from `../templates/rules-openapi-baseline.md`); a team
edit there counts like an ADR for the drift check. A deviation with neither an ADR nor a rules
edit behind it is a `Deferrals` entry ("needs ADR").

- OpenAPI **3.1.0** — nullability via `type: [string, null]`, never `nullable: true` (3.0 style).
- Error envelope **`{code, message, details?}`**, `code` = neutral `module.error_name` snake_case.
- **Cursor** pagination (`?after=&before=&limit=`) wrapped in `{items, has_next, has_prev, next_cursor}` — never offset.
- **URL** versioning (`/api/v1/...`) — never a `?v=2` query param.
- **BearerAuth** global; a public endpoint declares explicit `security: []`.
- `$ref` mandatory for shared schemas; placeholder data only in `example` blocks (no real PII).
